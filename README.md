# Контроль облачной инфраструктуры

## Этап 1

## 1. Назначение программы

Программа на языке C предназначена для анализа телеметрических измерений компонентов облачной инфраструктуры. Она обрабатывает последовательность измерений, рассчитывает производный показатель изменения, определяет состояние компонентов и проверяет наличие инцидентов по правилу.

## 2. Индивидуальный вариант

- **Вариант:** 20.
- **Компоненты:** `LAT`, `QRY`, `RPC`.
- **Порядок записи измерения:** значение → номер отсчёта → код компонента.
- **Разделитель полей и записей:** пробел.
- **Тип последовательности:** у одного компонента могут быть разные значения на одном отсчёте; учитываются все измерения.
- **Производный показатель `Q`:** нормированное изменение.
- **Параметры:** `k = 2`, `L = 0.8`, `D = 5`.
- **Формула показателя Q:** Q[i] = (X[i] − X[i−k]) / D
- **Правило состояния компонента — Сравнение с критерием L:\
  Q <− L: «СНИЖЕНИЕ»; −L ≤ Q ≤ L: «НОРМА»; Q> L: «РОСТ»
- **Правило инцидента (комбинация по компоненту):**
  Инцидент возникает, если первый компонент из списка находится в «ТРЕВОГА», а хотя бы один другой компонент не в «НОРМА».
- **Булево выражение инцидента:**
  `(st_lat != 0) && (st_qry != 0 || st_rpc != 0)`

## 3. Описание компонентов

Входные данные используют три кода компонентов:
- `LAT`
- `QRY`
- `RPC`
## 4. Формат исходных данных
Измерения записываются в одну строку, разделяются пробелами и повторяются в следующем порядке:
```text
значение номер_отсчёта код_компонента
```
Пример:\
Всего 5 отсчётов
```text
51.2 5 QRY 51.1 5 LAT 34.5 5 RPC 32.0 1 RPC 30.6 3 RPC 35.2 4 RPC 53.8 1 QRY 37.5 4 RPC 57.2 2 QRY 44.7 3 LAT 31.3 2 RPC 44.2 2 LAT 53.2 4 QRY 43.7 1 LAT 55.2 3 QRY 33.6 2 RPC 50.6 4 LAT 
```

Это означает, что на отсчёте `5`:  `QRY` = `51.2`, `LAT` = `51.1`, `RPC` = `34.5`\
Или же на отсчёте `3`: `LAT` = `44.7`, `QRY` = `55.2`, `RPC` = `30.6`

Значение — вещественное число, номер отсчёта — целое число(порядковый номер замера), код компонента — один из кодов `LAT`, `QRY`, `RPC`

## Этап 2

### 5. Алгоритм работы программы
Сначала в программе задаются константы по варианту (`k = 2`, `L = 0.8`, `D = 5`) и массивы со значениями компонентов за 5 отсчётов.
Дальше запускается цикл начиная с 3-го отсчёта (индекс `k`), потому что для первых двух отсчётов нет предыдущей пары с шагом 2. На каждом шаге для `LAT`, `QRY` и `RPC` через функцию `calc_q` считается показатель `Q` и через `get_state` определяется состояние компонента.
В конце шага проверяется условие инцидента: если `LAT` не в норме и хотя бы один из двух других компонентов тоже не в норме, то заполняется структура `Incident` и в консоль выводится строка с параметрами инцидента.

### 6. Организация данных
Значения за 5 отсчётов хранятся в обычных массивах `float lat[5]`, `float qry[5]` и `float rpc[5]`.
Для сохранения информации об инциденте используется структура из варианта:
```c
typedef struct {
    int time;
    int type;
    int count;
    float value;
} Incident;
```
Состояния компонентов в коде обозначены целыми числами: `-1` (СНИЖЕНИЕ), `0` (НОРМА), `1` (РОСТ).

### 7. Математическая модель и формулы производных показателей
Производный показатель Q (нормированное изменение) считается по формуле:

Q[i] = (X[i] − X[i−k]) / D

где `X[i]` — текущее значение, `X[i-k]` — значение 2 отсчёта назад (`k = 2`), `D = 5`.

Правило состояния компонента (сравнение с критерием `L = 0.8`):
- `Q < -0.8`: «СНИЖЕНИЕ»
- `-0.8 <= Q <= 0.8`: «НОРМА»
- `Q > 0.8`: «РОСТ»

Правило инцидента (комбинация по компоненту):
Инцидент возникает, если первый компонент из списка (`LAT`) находится в состоянии «ТРЕВОГА» (то есть не в «НОРМА»), а хотя бы один другой компонент (`QRY` или `RPC`) тоже не в «НОРМА».

Булево выражение для проверки в коде:
`(st_lat != 0) && (st_qry != 0 || st_rpc != 0)`

### 8. Контрольный пример

Если разобрать исходную строку по времени от 1 до 5 отсчёта, получатся такие значения:
- `LAT`: 1) 43.7, 2) 44.2, 3) 44.7, 4) 50.6, 5) 51.1
- `QRY`: 1) 53.8, 2) 57.2, 3) 55.2, 4) 53.2, 5) 51.2
- `RPC`: 1) 32.0, 2) 31.3 и 33.6, 3) 30.6, 4) 35.2 и 37.5, 5) 34.5
(для массива `RPC` на 2 и 4 отсчётах взяты значения 31.3 и 37.5, так как между ними самое большое изменение).

Ручной расчёт (при `k = 2`, `D = 5`, `L = 0.8`):

Отсчёт 3 (считаем с 1 отсчётом):
- `LAT`: Q = (44.7 - 43.7) / 5 = 1.0 / 5 = 0.20 — НОРМА
- `QRY`: Q = (55.2 - 53.8) / 5 = 1.4 / 5 = 0.28 — НОРМА
- `RPC`: Q = (30.6 - 32.0) / 5 = -1.4 / 5 = -0.28 — НОРМА
Инцидента нет, все показатели в пределах от -0.8 до 0.8.

Отсчёт 4 (считаем со 2 отсчётом):
- `LAT`: Q = (50.6 - 44.2) / 5 = 6.4 / 5 = 1.28 — РОСТ (больше 0.8)
- `QRY`: Q = (53.2 - 57.2) / 5 = -4.0 / 5 = -0.80 — НОРМА (входит в границы)
- `RPC`: Q = (37.5 - 31.3) / 5 = 6.2 / 5 = 1.24 — РОСТ (больше 0.8). Если проверить остальные пары RPC на этом отсчёте: (35.2 - 31.3)/5 = 0.78, (35.2 - 33.6)/5 = 0.32, (37.5 - 33.6)/5 = 0.78 — они в норме.
Здесь `LAT` и `RPC` вышли за порог, поэтому фиксируется инцидент: отсчёт 4, тип 1, проблемных компонентов 2, значение по первому компоненту 1.28.

Отсчёт 5 (считаем с 3 отсчётом):
- `LAT`: Q = (51.1 - 44.7) / 5 = 6.4 / 5 = 1.28 — РОСТ
- `QRY`: Q = (51.2 - 55.2) / 5 = -4.0 / 5 = -0.80 — НОРМА
- `RPC`: Q = (34.5 - 30.6) / 5 = 3.9 / 5 = 0.78 — НОРМА
Инцидента нет, потому что кроме `LAT` остальные компоненты в норме.

Вывод программы в консоли:
```text

Параметры: k = 2, L = 0,8, D = 5,0

--- Отсчет 3 (пара с отсчетом 1) ---
LAT: X[3]=44,7, X=43,7 -> Q = 0,20 | НОРМА
QRY: X[3]=55,2, X=53,8 -> Q = 0,28 | НОРМА
RPC: X[3]=30,6, X=32,0 -> Q = -0,28 | НОРМА
-> Инцидентов нет

--- Отсчет 4 (пара с отсчетом 2) ---
LAT: X[4]=50,6, X=44,2 -> Q = 1,28 | РОСТ
QRY: X[4]=53,2, X=57,2 -> Q = -0,80 | НОРМА
RPC: X[4]=37,5, X=31,3 -> Q = 1,24 | РОСТ
-> ИНЦИДЕНТ! time=4, type=1, count=2, value=1,28

--- Отсчет 5 (пара с отсчетом 3) ---
LAT: X[5]=51,1, X[3]=44,7 -> Q = 1,28 | РОСТ
QRY: X[5]=51,2, X[3]=55,2 -> Q = -0,80 | НОРМА
RPC: X[5]=34,5, X[3]=30,6 -> Q = 0,78 | НОРМА
-> Инцидентов нет
```

Сравнение ручного расчёта и программы:

| Отсчёт | Компонент | Ручной расчёт | Вывод программы | Статус |
| :--- | :--- | :--- | :--- | :--- |
| 3 | LAT, QRY, RPC | 0.20, 0.28, -0.28 | 0.20, 0.28, -0.28 | Совпадает (инцидентов нет) |
| 4 | LAT, QRY, RPC | 1.28, -0.80, 1.24 | 1.28, -0.80, 1.24 | Совпадает (инцидент, count=2) |
| 5 | LAT, QRY, RPC | 1.28, -0.80, 0.78 | 1.28, -0.80, 0.78 | Совпадает (инцидентов нет) |

Результаты программы полностью сошлись с ручным счётом.
